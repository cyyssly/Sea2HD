# GRAPH 管线（整块位图窗口）与遮挡判定改造

日期：2026-11-21
相关代码：`src/misc/sea2_hd.cpp`

## 1. 问题与定位

三个现象看似无关，最后收敛到同一处：

| 现象 | 触发 |
|---|---|
| 建筑内左右面板美术字变模糊 | 进 building |
| 港口打开侧边主菜单后同样变模糊 | 开菜单 |
| 价格输入的计算器被面板高清盖住 | 进市场输入价格 |

模糊不是"文字被重画"：标签是烘焙进 `assets/hd/FRAMES/port.png` 的，内景管线
（`draw_scene_picture`）只处理 104,56 处 136x112 的小画，碰不到面板。

真正的根因是 `draw_frame_picture` 第二遍的**逐格颜色比对**：它拿素材的预测色和
当前帧像素逐点比较，超过 `FramePicturePixelTolerance(24)` 就静默跳过该格，退回 4x
最近邻。建筑内整屏由另一块 `graph.dat` 数据重建，港口开菜单后面板被局部重画，
两者都会让面板格的像素与参考不再逐点相等，于是大面积跳过 → 模糊。

而计算器（GRAPH 记录 1，136x152）是装饰性位图拼出来的，既不是纯色填充矩形，
也就永远进不了窗口候选——它需要一条自己的识别管线。

## 2. 遮挡判定改造

原则：**画不画高清由"谁后写"决定，不由颜色决定。**

1. **整屏重绘单独设基准**
   `window_finalize_candidate` 里，面积达到 `WindowMaxScreenPercent` 的写入批次
   不再被丢弃，而是更新 `frame_base_order` 并作废更早登记的窗口（日志
   `FRAMEBASE`）。港口 / 航海 / 建筑三处整屏重绘因此无条件铺满高清。

2. **删除逐格比色**
   `draw_frame_picture` 第二遍只剩两道判定：素材 alpha、遮挡掩码。淡入、换调色板、
   另一份整屏数据都不再影响"画不画"。

3. **矩形级内容判定**
   `rect_is_overlay` 在矩形内部稀疏采样，与参考框体比对：不一致超过 12% 才算
   真遮挡；一致则说明"游戏把框体自己重画了一遍"，撤掉掩码照常画高清
   （日志 `RECTKEEP ... type=frame`）。这让放宽边框预筛变得安全。

4. **边框预筛放宽**
   `WindowRingStrongPercent` 70 → 60：贴边菜单有一条边与面板同色，实测整体
   67%、最弱边 12%，原来会被判掉。次序过滤增加 `frame_base_known`，建筑内复用
   港口框体（从未建立基准）时不再误杀 `order=0` 的窗口。

5. **窗口恢复同步**
   `window_restore_pixels` 跳过基准次序之前的矩形与本帧判定为框体重画的矩形，
   避免高清画好之后又被改回 4x。

## 3. GRAPH 管线

### 3.1 目录约定

```
assets/original/GRAPH/<名字>.png   游戏原始分辨率的基准图（尺寸取自 PNG 本身）
assets/hd/GRAPH/<名字>.png         4 倍高清图，可带 alpha
```

高清图缺失不报错：仍识别、仍打日志，并按低清像素显示（见 3.3）。
文件名只作标识，`-136x152` 这类后缀不参与解析。

### 3.2 识别

与内景不同，GRAPH 图没有固定落点（同一张图可能出现在画面不同位置），因此：

- **加载**：跳过面积超过半屏的图（640x400 的记录 4/5/23/25/27 归 FRAMES 管线），
  日志 `GRAPHSKIP` / `GRAPHLOAD count=`；
- **搜索**：参考图 4x4 等分取 16 个锚点，全屏按 1 像素步长给每个落点打分，
  只对最优落点做逐像素确认；未命中时限流为每 4 次绘制调用搜一次（独立计数
  `graph_search_tick`，不用 `composite_count`——静态画面上它可能长期不动）；
- **判定**：16 个锚点**全部命中**，且整图一致率 ≥60%。锚点是主判据，一致率
  只用来拦住"形状对、内容完全不同"；计算器显示区里是玩家实时输入的数字，
  与参考必然不同，实测一致率 74%，因此不能把一致率设成硬门槛；
- **记忆**：命中后只在该位置原地核对，成本几乎为零。

日志：`GRAPHMATCH <名字> x=.. y=..`、失败时 `GRAPHSCAN best=.. pct=..`。

### 3.3 绘制

在 `draw_port_picture` 之后调用（建筑内是港口子状态），按三种情况处理：

1. 有高清图：逐像素写入 4 倍图，alpha < 50% 的像素跳过，然后 `mark_hd_art`
   标记该区域，避免被 `window_restore_pixels` 改回；
2. 无高清图：把该矩形从低清帧缓冲按 4 倍最近邻写回，等于**从面板高清手里
   把这块收回来**。没有这一步，`port.png` 的面板高清会整块盖住窗口；
3. 被活跃窗口（对话框等）压住：不画，交给游戏原样显示（日志 `GRAPHCOVER`）。

### 3.4 素材要求

- 尺寸必须正好是原图的 4 倍（`graph-001`：136x152 → 544x608）；
- 无 alpha（24bpp）也合法：按 RGBA 读取时 alpha 全为 255，整块写入；
- 显示区画成空底即可，玩家输入的数字由文字管线在 HD 之后叠加绘制。

## 4. 日志速查

| 日志 | 含义 |
|---|---|
| `FRAMEBASE order=.. dropped=..` | 整屏重绘建立新基准，作废旧窗口 |
| `RECTKEEP ... type=frame` | 矩形内容与参考一致，判定为框体自身重画，撤掩码 |
| `GRAPHSKIP <名字> ... fullscreen` | 整屏 GRAPH 图，交给 FRAMES |
| `GRAPHLOAD count=N` | 进入管线的 GRAPH 图数量 |
| `GRAPHMATCH <名字> x=.. y=..` | 识别命中 |
| `GRAPHSCAN <名字> best=.. pct=..` | 未命中时的最优落点与一致率 |
| `GRAPHCOVER <名字> ...` | 命中但被窗口压住，不绘制 |

## 5. 已知限制

- 目前只有 `graph-001`（计算器）配了高清图，其余 GRAPH 图只做识别；
- 同一落点若出现两张尺寸接近的 GRAPH 图，需要靠锚点 + 一致率区分，尚未实测；
- 装饰性窗口（如市场右侧菜单）仍走 `window_verify` 的边框签名核对，
  它的遮挡最终由 `rect_is_overlay` 决定，两者不一致时以 `rect_is_overlay` 为准。
