## 3. `1.PAT` 字库文件结构

### 3.1 物理布局

- 文件大小 **173112 字节**（`sea2\1.PAT`）。
- 每 **512 字节扇区** 装 **18 个 28 字节字形**，扇区尾部留 **8 字节填充**。
- 无文件头，记录号 0 从文件偏移 0 开始。
- 记录号 → 文件偏移：

```
offset(record) = 28 * record + 8 * (record / 18)     // 整数除法
```

- `173112 = 6086 × 28 + 8 × 338`，即文件恰好容纳 **6086 个完整字形槽（0..6085）**，末尾没有残余字节。`1.PAT` 旁边还有一个 `2.PAT`（217600 字节，425 扇区 × 18 = **7650 槽**，同样的 28 字节 16×14 格式），存放 **Big5 二级字**，已定性并有独立 HD 图集，详见 `koukai2-extra-assets-2026-11-08.md` 第 5 节。

### 3.2 三段内容分布

| 记录区间 | 槽位数 | 特征 | 判断 |
| --- | --- | --- | --- |
| 0 – 683 | 684 | 664 个互不相同 + 2 个全零 | 非 level-1 区（ASCII/假名/符号等），未纳入本轮映射 |
| **684 – 6084** | **5401** | **5401 个位图全部互不相同，无全零** | **Big5 level-1（常用字）区块** |
| 6085 | 1 | 唯一、非零、且不与上述任一记录重复 | 额外字形，用途未确认 |

关键事实：**684..6084 的槽位数 5401 恰好等于 Big5 level-1 字符数**（lead `A4`–`C6`，低级字节 `40`–`7E` 共 63 个 + `A1`–`FE` 共 94 个；34 个 lead × 157 + `C6` 行 63 = 5338 + 63 = **5401**）。同时该区间 5401 个 28 字节位图**两两互不相同**，这排除了"同一字形被多个记录复用"的可能，也是"记录号 ↔ 字符"可以做成一一映射的物理基础。

### 3.3 记录区间不是严格线性排列

如果记录 684 起严格按 Big5 序排列，那么 `big5_index = record - 684` 恒成立。实测**不成立**，字体内部有 4 处整体偏移段（字体里混入少量非 level-1 字形，也缺失少量 level-1 字）：

| 记录区间 | 长度 | 偏移 d | 含义 |
| --- | --- | --- | --- |
| 684 – 2095 | 1412 | 0 | 与 Big5 序对齐 |
| 2096 – 2519 | 424 | **+1** | 字体缺了 1 个 level-1 字（索引前跳 1） |
| 2520 – 4396 | 1877 | 0 | 重新对齐 |
| 4397 – 4784 | 388 | **−1** | 字体多插了 1 个非 level-1 字形 |
| 4785 – 5312 | 528 | 0 | 重新对齐 |
| 5313 – 5499 | 187 | **−1** | 再插入 1 个 |
| 5500 – 5582 | 83 | 0 | 重新对齐 |
| 5583 – 5729 | 147 | **−1** | 再插入 1 个 |
| 5730 – 6084 | 355 | 0 | 重新对齐，直到结尾 |

映射公式：

```
big5_char = big5_level1[ (record - 684) + d(record) ]
```

偏移段只在边界处做整体平移，**段内是严格线性**的。

## 4. 记录号 → 字符 映射的定稿

### 4.1 定稿方法（三步）

1. **打分**：把每条记录的 28 字节位图展开成 16×14 位图；用 `simsun` / `msjh` 在 **14–18px** 直接小字号渲染候选字符（不做拉伸），同一字符多字号取最好的；再对每个候选做 **9 向 ±1 像素平移**，取与位图的 **最大 IoU**。对 `d ∈ {-2,-1,0,+1,+2}` 五个假设各算一次，得到 `score3_S.npy`（**5401 × 5，float32，取值 0–1**）。
2. **DP 求粗分段**：状态 = 偏移量 d，转移惩罚 `λ·|d_prev − d|`，起点固定 d=0，终点自由：

```
dp[i][k] = max_{kp} ( dp[i-1][kp] − λ·|kp − k| ) + S[i][k]
```

   `λ = 1/2/4/8/16` 得到的分段结构完全一致，说明分段结论对惩罚强度不敏感。
3. **滑窗过零点精确定界**：单条记录的 argmax 噪声太大（DP 边界会偏早 1–2 条），改为对 `S[d−1] − S[d0]` 做 **21 条居中滑动窗口平均**，窗口均值过零的位置即边界。由于窗口居中，阶跃处**无系统偏移**。

### 4.2 测量得到的边界（`cross.py`）

| 事件 | 窗口均值过零点 |
| --- | --- |
| 段 A 起点（d0 → d−1） | ≈ 4396.6 |
| 段 A 终点（d−1 → d0） | ≈ 4784.0 |
| 段 B 起点 | ≈ 5312.6 |
| 段 B 终点 | ≈ 5499 |
| 段 C 起点 | ≈ 5582.6 |
| 段 C 终点 | ≈ 5728.9 |

按整数记录取整后即 4.1 节/3.3 节的分段表（4397 起、4784 止；5313 起、5499 止；5583 起、5729 止）。

### 4.3 DP 无法表达"某条记录不是字符"

DP 只能给每条记录指派一个偏移量，因此**不能表达"这条记录不是 Big5 字符"**。平段位移的结果里出现了重复索引（1836、3712、4626、4899 附近）和跳空索引，正是"字体含非 level-1 字形 / 缺失 level-1 字"的体现。结论：**段边界附近最多有 ±1 条记录无法靠位图单独定论**，这部分属于已知不确定性（见第 8 节）。

## 6. 运行时管线

整条链路只做一件事：**把游戏真正画出来的那个 16×14 汉字格，换成图集里对应的 64×56 简体瓦片**。

### 6.1 第一环：DOS 读钩子（28 字节 → 记录号）

- `SEA2_HD_TraceDosRead()`（`sea2_hd.cpp:1080`）拦截游戏对字库文件的读取。
- 一次读取正好 **28 字节**时，把这 28 字节**整体**作为 key、记录号作为 value 存入 `glyph_index`（`std::unordered_map<GlyphMask, uint16_t>`，`GlyphMask = std::array<uint8_t,28>`）。
- 用完整 28 字节做 key，意味着**要么精确命中、要么查不到**，不存在哈希碰撞把某个字认成另一个字。
- 同时把最近读到的记录号记到 `pending_glyph_record`，供下一环使用。

### 6.2 第二环：blitter 入口

- `SEA2_HD_TraceBlitterEntry()`（`sea2_hd.cpp:1250`）在通用平面 blitter 入口处执行：
  - `lookup_glyph_bitmap()`（`:722`）用源位图查 `glyph_index` 拿到 `record`；
  - 只要不是空白位图、且（本轮有读字库记录 / 查到了记录 / 调用者是文本路径），就 `register_text_cell(x*8, y)`（`:740`）把这一格登记为"文本格"。
- **注意**：这一步只登记"哪一格是文本"，不缓存"这一格是什么字"。字是每帧重新识别的。

### 6.3 第三环：每帧识别

- `identify_text_cell()`（`:766`）从当前帧缓冲读取该格 16×14 像素，按三条规则判定是否仍为文本格：
  1. 该格不同颜色数 **≤ 3**（正文色 + 最多两级抖动背景色）；
  2. 正文色像素数在 **4 – 150** 之间（排除空白与近似实心块）；
  3. 满足以上两条即认为"这格现在是文字"，去查 `glyph_index` 得到当前记录号。
- 因为每帧都重新读帧缓冲，**高亮变色、菜单重绘、窗口遮挡都不会永久破坏识别**——最坏只丢一帧。

### 6.4 第四环：合成

- `draw_text_cell()`（`:840`）用 `idx = record - 684` 取图集瓦片（`:856-857`），把 64×56 alpha 瓦片按当前正文色着色后写入合成画布。
- 图集加载在 `glyph_atlas` 相关代码（`:612-685`）：校验尺寸必须等于 `64 × GlyphTileWidth` × `rows × GlyphTileHeight`，逐块统计墨迹像素，`ink >= 32` 才标记为可用，避免空瓦片覆盖原字。
- 未命中的格子 `continue`，保留原画面。

### 6.5 现有诊断能力（保留）

- `SEA2_HD_DumpStringTrace()`（`:1440`）、`SEA2_HD_ProfileIp()`（`:1394`）、`SEA2_HD_ScanFont()`（`:1012`）、`SEA2_HD_VerifyGlyphMap()`（`:1753`）等侦察/校验函数仍在，仅在 trace 模式下输出。
- 曾用于定位的 `debug_glyph_line()` 逐帧写文件调试函数**已按要求删除**（`grep debug_glyph` 已无匹配）。

## 9. 已知限制与未完成项

### 9.1 已确认的限制

1. **段边界 ±1 条记录不确定**：≈4397 / 4784 / 5313 / 5499 / 5583 / 5729 六个边界处，各有最多 1 条记录无法仅凭位图区分（DP 模型无法表达"该记录不是字符"）。
2. **`1.PAT` 记录 6085 未定性**：唯一、非零、不与 684..6084 重复，用途未确认；当前映射不覆盖它。
3. **记录 0–683 未映射**：684 个槽位里 664 个唯一 + 2 个全零，属于 ASCII/假名/符号等非 level-1 区，本轮未处理。
4. **只有走 blitter 的文本格会被 HD 覆盖**：存档列表等画面里不走该 blitter 的文字仍是原字库渲染。
5. **`2.PAT` 已定性**：7650 槽 × 28 字节 16×14，是 Big5 二级字（第 n 槽 = 二级字第 n+1 个，码位 0xC941..0xF9D4），不是 16×16/32 字节图形块；其 HD 图集 `assets/hd/font2_atlas.png` 已接入运行时。数字/ASCII 半角 HD 化仍未做，且与 `2.PAT` 无关。
6. **「知力 → 知证」仍缺直接证据**：本轮日志中**没有出现 `look=3508`**，该处修复依赖映射表本身，而非运行时抓到的日志。

### 9.2 未实现的素材类型

- KAO48（48×48 发现物/物品）、PORTCHIP（港口瓷砖）、港口侧栏固定标签：**均未支持**。
- 不得在说明中把这些描述为已支持。

### 9.3 若要继续推进的候选方向（未被要求，仅记录）

- 用 `look=3508` 日志补齐「知力」证据：进角色情报页停留 2–3 秒即可采到。
- 放宽 `width == 2 && height == 16` 的 blitter 判定，覆盖更多文本路径。
- 解析半角数字/ASCII 字形（`2.PAT` 不含这类字形，它整份都是 Big5 二级汉字）。
- 港口侧栏标签走的是固定字符串路径，需要单独定位其绘制入口。
